# CPU対戦の行動ルール

ホーム画面で4種類から選択できます。「もう一度」は同じ種類を引き継ぎます。

| CPU | 攻撃 | 防御 |
| --- | --- | --- |
| ① 全履歴の頻度解析 | 相手の公開済み配置履歴から得失点の期待値を推定 | 相手の攻撃履歴から配置ごとの得失点の期待値を推定 |
| ② ランダム | 残存箱を一様に選択 | 異なる2箱を一様に選択 |
| ④ 高得点狙い | 残っている8・10・12点から一様に選択 | 高得点箱を優先し、必ずシールドの点数をハートより大きくする |
| ⑤ 最近5件の頻度解析 | 相手の配置履歴の直近5件で①と同じ推定 | 相手の攻撃履歴の直近5件で①と同じ推定 |

①⑤は10%の確率で合法な行動を一様に選び、残り90%は推定値が最大の行動を選びます。同点候補は一様に選択します。

## 頻度の推定

自分の攻撃時に公開された履歴は相手の配置分析に、自分の防御時の履歴は相手の攻撃分析に使います。⑤は役割別に絞り込んだ後で直近5件を採用します。

各箱について「選ばれた回数 / その箱が存在した回数」を基準に、一様事前分布1観測分で平滑化します。残存箱数をNとすると `(選ばれた回数 + 1/N) / (存在した回数 + 1)` を計算し、現在の残存箱で合計1になるよう正規化します。履歴がない場合の頻度は一様です。

- 攻撃評価値：`P(ハート) × 箱の点数 − P(シールド) × シールド命中時の推定失点`
- 推定失点：分析対象の履歴のうち、その箱がシールドだったときのハート点数の平均。未観測なら現在の他の箱の平均点数。
- 防御評価値：`ハートの点数 × (P(シールド箱が攻撃される) − P(ハート箱が攻撃される))`

頻度が一様でも、攻撃は箱の点数によって評価値が異なります。この評価は1行動の得失点を対象とし、勝率の保証や箱破壊後の先読みは行いません。未公開の配置は参照しません。試合をまたぐ履歴の保存はありません。

## 高得点狙いの補足

高得点箱が2個以上なら、その中の合法な配置ペアを一様に選びます。1個ならその箱にシールド、低得点箱にハートを置きます。高得点箱がない場合は残存箱を使い、点数の大小条件を維持します。

## 呼び出しと検証

`createCpu(type, random)` に `frequency` / `random` / `high-value` / `recent` を指定します。乱数関数を注入して対戦を再現できます。全種類が既存の `PlayerController` と同じ非同期インターフェースを使います。

`node --test`：18テスト成功。新規テストでは全残存箱パターンの合法性、履歴の役割分離、直近5件の切り出し、頻度補正、探索、入力不変性、全16組み合わせ320試合の終了と再現性を確認しています。既存のランダム対戦5,000試合テストも成功しています。これらは動作検証であり学習ではありません。
