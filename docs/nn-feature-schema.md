# NN入出力仕様 v1

2026-11-04更新：シールド命中時はシールド箱の点数を防御側が獲得します。モデルのルール情報に `shieldScoring: "shield-box"` を追加。現在の仕様は [shield-scoring-change.md](shield-scoring-change.md) を優先します。

識別子：`heartbox-v1`。固定箱順は `[4,6,8,10,12]`。入力は203個の有限数値です。現在の公開 `GameView` だけを使用し、現在の非公開配置、相手CPU種別、将来の結果は渡しません。

## 入力の固定順序（0始まり）

| 添字 | 内容 |
| --- | --- |
| 0–4 | 現在の箱の生存フラグ |
| 5–6 | 自分・相手の得点÷45。上限超過時もクリップしない |
| 7 | 現在ターン÷15 |
| 8 | step（0または1） |
| 9 | 自分が攻撃なら1、防御なら0 |
| 10–11 | 自分・相手の得点到達ターン÷15。公開履歴の最後の加点から復元、未加点なら0 |
| 12–44 | 相手の全履歴統計、11要素×3ブロック |
| 45–77 | 相手の直近5件統計、11要素×3ブロック |
| 78–202 | 直近5攻撃の記録、25要素×5件 |

統計ブロックはハート配置、シールド配置、攻撃先の順です。配置は相手が防御した履歴、攻撃先は相手が攻撃した履歴から求めます。直近5件は役割を絞った後に切り出します。

各11要素は、固定箱順の頻度5個、その箱が生存していた観測回数5個、対象履歴件数1個です。頻度は選択回数÷生存観測回数（未観測なら0）。観測回数と件数は全履歴なら15、直近なら5で割ります。NN入力の統計は平滑化・再正規化しません。頻度解析CPUの方策とは異なる特徴量定義です。

直近記録は古い順。5件未満では末尾を0で埋めます。各25要素は、実在マスク1個、攻撃者が自分か1個、当時の生存フラグ5個、ハート・シールド・攻撃先のone-hot各5個、結果one-hot3個（heart/shield/empty）の順です。

## 出力

行動仕様：`heartbox-actions-v1`。0–4は固定箱順の攻撃。5–24はハートを外側、シールドを内側のループにした順序付きペア（同じ箱を除外）です。

攻撃時は0–4のみ、防御時は5–24のみを使用します。破壊済みの箱を含む行動はマスクで確率0にします。softmax後の確率に従って抽選し、最大値固定にはしません。

NNは203→64→64の共通tanh層と、25行動logit・1価値の線形出力。JSON重みは `[出力][入力]` の順です。JSONには特徴量・行動仕様のバージョン、箱、最大15ターン、45点先取を含め、読み込み時に照合します。

特徴量は学習時もJavaScriptで生成してPythonへ渡すため、本番でPython側の再実装は使いません。Pythonの独立した参照実装はテスト専用です。同一公開状態の特徴量と同一重みのlogit・確率を照合します。
