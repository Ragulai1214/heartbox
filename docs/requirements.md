# HEART BOX 確定要件

## 2026-10-29 更新

試合の上限を15ターン（最大30攻撃）に変更する。CPU対戦・ローカル対戦とも共通。45点先取と同点時の到達ターン比較は維持する。NN CPUの実装・学習は別工程とする。

2026-10-28。仕様書の曖昧な点について、推奨案を採用するというユーザーの指示に基づく。本書と仕様書が異なる場合は本書を優先する。

- 配置ボタン選択中は空箱への配置だけを受け付ける。配置成功時にボタン選択を解除する。
- ボタン未選択時に配置済みの箱を押すと移動元になる。次に空箱を押すと移動、中身のある箱を押すと交換する。同じ箱を押すと選択解除する。別の配置ボタンを押すと移動元選択を解除する。
- 攻撃確定時に得点・破壊・公開履歴を更新し、勝敗も確定する。最終攻撃もREVEALで見せ、次へでRESULTに進む。確定後の追加攻撃は受け付けない。
- REVEAL中は攻撃前の箱を表示し、今回破壊した箱を灰色にする。続行する試合では次へで壊れた箱を除いて詰める。残り2箱なら初期5箱に戻す。2箱での配置は行わない。
- 空箱数は生存箱数から2を引いた数。攻守が替わるたびに全配置を初期化する。
- CPU対戦ではAが人間、BがCPU。CPU操作は自動で進め、公開後の次へは人間が押す。人工的な待ち時間・演出は入れない。
- 配置途中と確定後の非公開配置はGameState・GameView・公開履歴に含めず、入力処理と進行処理で保持する。HANDOFFとATTACKのDOMにも中身を残さない。
- 勝敗結果は勝者（引き分けはnull）、理由、到達ターンを保持し、結果画面はその値を表示する。
- 履歴はモーダル表示し、背面を操作させない。閉じると元の画面と入力状態を復元する。結果画面から開いた場合の戻り先は結果画面とする。
- 初回の履歴は「公開済みの履歴はありません」と表示する。
- 再試合ではゲーム状態と入力待ちを初期化し、初手を再抽選する。連打で処理を重複させない。
- 試合の保存・再開は今回の対象外。ページを再読み込みした場合はホームから始める。
- 最小限の明るい画面とし、箱はスマホでも横一列に保つ。キーボードでボタンを操作でき、選択状態を色だけに頼らず示す。
- ローカル実装と自動テストを先に完了する。GitHub公開は公開先と認証を確認してから行う。実機スマホと人間同士の検証は未実施ならその旨を記録する。
