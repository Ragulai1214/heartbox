# HEART BOX 仕様書(試作)

ビルド工程なしのHTML・CSS・JavaScriptで作る、CPU対戦とローカル対戦のプロトタイプ仕様。確定した仕様だけを書き、未確定の点は末尾にまとめる。

確定要件は `docs/requirements.md` を参照する。以下の本文と競合する場合は確定要件を優先する。

## 概要

プロトタイプの目的は、HEART BOXの読み合いが成立するかを、最小の実装で早く試すこと。

### 導入するもの

- ルール層(判定、得点、箱の破壊、リロード、勝利判定)
- CPU対戦(ランダム)とローカル2人対戦
- ローカル対戦用の交代画面
- 履歴ポップアップ(試合中と結果画面から開ける)
- 画面はホーム、ゲーム、結果の3つ

### 導入しないもの

アイテム、通信対戦、点数配分のランダム選択、制限時間、ポーズ画面、演出、ルール説明画面。

### 技術構成

| 項目 | 内容 |
| --- | --- |
| 言語 | HTML、CSS、素のJavaScript(ES Modules)。ビルド工程なし、外部ライブラリなし |
| 画面 | 1つのHTMLページの中で、ホーム・ゲーム・結果の表示を切り替える |
| テスト | node(組み込みのテストランナー)でルール層を検証する |
| 公開 | GitHub Pages(mainブランチのルートを公開元にする) |
| 管理 | VS CodeからGit、GitHubで管理 |
| 実装 | Codex。この仕様書を docs/spec.md としてリポジトリに置いて参照させる |
| アセット | 必要なら自作 |

## ゲームルール

2人対戦。攻守を入れ替えながら、箱に仕込まれたハートとシールドを読み合い、先に45点を取るか、10ターン終了時に点が高い方が勝つ。

### 盤面

- 箱は5つで、点数は 4 / 6 / 8 / 10 / 12 に固定する
- 横一列に並べ、点数の小さい順に左から置く
- 壊れた箱は詰めて並べ直す(8と12が壊れたら 4 / 6 / 10)
- 箱は位置ではなく点数で識別する(1サイクル内で点数は重複しない)

### 1ターンの流れ

1ターン=両プレイヤーが防御と攻撃を1回ずつ行う(攻撃処理が計2回)。

1. 最初の攻撃側をランダム(50%)で決める
2. 防御側が、ハート1つとシールド1つを別々の箱に非公開で置く。残りの箱は空箱(生存箱数から2を引いた数)
3. 攻撃側が箱を1つ選んで攻撃する
4. 判定し、配置を両者に公開する
5. 攻守を入れ替えて、2〜4をもう一度行う(ここまでが1ターン)

### 判定

| 攻撃した箱 | 結果 | 箱 |
| --- | --- | --- |
| ハート | 攻撃側がその箱の点数を獲得 | 壊れる |
| シールド | 防御側がハートの箱の点数を獲得 | 残る |
| 空箱 | 両者とも得点なし | 壊れる |

### リロード

生きている箱が3つの状態で1つ壊れ、2つになった時点で、5箱(4 / 6 / 8 / 10 / 12)に戻す。それ以外のタイミングでは戻さない。

### 勝利条件

1. どちらかが45点以上になった時点で、その攻撃処理の直後に終了し、その側の勝ち(ターンの途中でも終了する)
2. 10ターン終了時に得点が違えば、高い方の勝ち
3. 10ターン終了時に同点なら、その得点に早いターンで到達した方の勝ち(ターン単位で比べ、同じターン内の順番は見ない)
4. 到達したターンも同じなら引き分け。両者0点のまま終わった場合も引き分け

## データ構造

ルール層は、DOMにもブラウザAPIにも触れない純粋なJavaScript(関数とクラス)で書く。画面なしで、nodeから10ターン回せるようにする。

```js
// js/core/constants.js
export const BOX_VALUES = [4, 6, 8, 10, 12];
export const TARGET_SCORE = 45;
export const MAX_TURNS = 10;

export const Content = Object.freeze({ NONE: 0, HEART: 1, SHIELD: 2 });
export const HitKind = Object.freeze({ HEART: 'heart', SHIELD: 'shield', EMPTY: 'empty' });
export const Phase = Object.freeze({
  PLACE_READY: 'place_ready',
  PLACE: 'place',
  HANDOFF: 'handoff',
  ATTACK: 'attack',
  REVEAL: 'reveal',
  RESULT: 'result',
});
```

### 配置

配置中の箱は、点数をキーにしたオブジェクトで持つ。初期状態はすべて NONE。

```js
const boxes = { 4: Content.NONE, 6: Content.NONE, 8: Content.NONE, 10: Content.NONE, 12: Content.NONE };
```

- 入力は、選んだ箱のキーに Content を代入する形で表す
- 配置が確定するまで、この配置は GameState に入れない(攻撃側に渡す状態へ混ざらないようにする)
- オブジェクトのキーは文字列になるので、点数として使う時は Number() で戻す

### 履歴1件(攻撃処理1回につき1件、公開後にだけ追加)

```js
/**
 * @typedef {Object} TurnRecord
 * @property {number}   turn        1〜10
 * @property {number}   step        ターン内の何回目か(0 or 1)
 * @property {number}   attacker    0 or 1
 * @property {number[]} boxesAlive  その時点で生きていた箱の点数(昇順)
 * @property {number}   heart       ハートがあった箱の点数
 * @property {number}   shield      シールドがあった箱の点数
 * @property {number}   picked      攻撃された箱の点数
 * @property {string}   kind        HitKind の値
 * @property {number}   gain        動いた得点(0なら動かず)
 * @property {number}   gainTo      得点した側(-1=なし)
 * @property {number[]} scoresAfter 攻撃処理後の累計 [A, B]
 */
```

### ゲーム状態

```js
// js/core/gameState.js
export function createGameState(firstAttacker) {
  return {
    boxesAlive: [...BOX_VALUES],  // 生きている箱の点数(昇順)
    scores: [0, 0],
    turn: 1,
    step: 0,
    firstAttacker,                // 開始時に50%で決定
    reachedTurn: [0, 0],          // 最後に得点が増えたターン(同点判定用)
    history: [],                  // TurnRecord の配列
    phase: Phase.PLACE_READY,
  };
}
```

- 攻守は保存せず、step から計算する。step 0 は firstAttacker が攻撃、step 1 は反対側が攻撃
- reachedTurn は、得点が増えた攻撃処理のターン番号で更新する

## 進行フェーズと操作

### フェーズ(攻撃処理1回ごとに繰り返す)

| フェーズ | 内容 | 次へ進む条件 |
| --- | --- | --- |
| PLACE_READY | ローカル対戦のみ。「Aさんの配置です。Bさんは画面を見ないでください。」を表示 | 配置側が[準備OK]を押す |
| PLACE | 防御側がハートとシールドを置く | 2つ置いて[確定]を押す |
| HANDOFF | ローカル対戦のみ。箱の中身を伏せ、「配置が完了しました。Bさんに端末を渡してください。」を表示 | 攻撃側が[Bさんです]を押す |
| ATTACK | 攻撃側が箱を選ぶ | 箱を選んで[攻撃]を押す |
| REVEAL | 判定し、配置を透過表示して両者に公開。履歴に1件追加 | [次へ]を押す |

REVEAL のあと、終了判定を行う。45点に届いたか、10ターンを終えていれば RESULT へ、そうでなければ攻守を入れ替えて PLACE_READY(CPU対戦では PLACE)へ戻る。箱が2つになっていたら、ここでリロードする。

CPU対戦では PLACE_READY と HANDOFF を出さない。

### 配置の操作(クリックとタップで共通)

- 画面下に[ハート][シールド]のボタンを置く(ハートが左、シールドが右)
- ボタンを選んでから、空の箱を選ぶと、その箱に置かれる
- 配置ボタン選択中は、すでに何かが置かれている箱を選んでも何も起きない。配置成功時にボタン選択を解除する
- ハートまたはシールドが盤上に置かれている間は、そのボタンをグレーアウトして押せなくする
- 置き直しは、置いた箱を選んでから、別の箱を選ぶ。移動先が空なら移動、何かが置かれていれば2つの中身を入れ替える
- 2つとも置くと[確定]が押せるようになる。確定前なら置き直せる

```js
// js/core/placement.js
export function placeFromButton(boxes, content, toValue) {
  if (boxes[toValue] !== Content.NONE) return false;         // 何か置かれている箱には置けない
  if (Object.values(boxes).includes(content)) return false;  // その種類はすでに盤上にある
  boxes[toValue] = content;
  return true;
}

export function swapBoxes(boxes, fromValue, toValue) {
  const tmp = boxes[toValue];         // 移動先の値を退避
  boxes[toValue] = boxes[fromValue];  // 移動元の値を移動先へ
  boxes[fromValue] = tmp;             // 退避した値を移動元へ
}

export function canConfirm(boxes) {
  const values = Object.values(boxes);
  return values.includes(Content.HEART) && values.includes(Content.SHIELD);
}
```

### 攻撃の操作

- 攻撃する箱を選ぶと、その箱の枠が強調される。選び直せる
- [攻撃]を押すと確定し、判定へ進む

## 画面仕様

履歴と交代画面は別ページにせず、ゲーム画面の上に重ねるオーバーレイ(Webのポップアップのような表示)にする。ホーム、ゲーム、結果は、1つのHTMLページの中で表示を切り替える。

### ホーム画面

[CPU対戦]と[ローカル対戦]の2ボタン。押すと、そのモードで新しい試合を始める。見た目は最小限でよい。

### ゲーム画面

```
[履歴]                       45点先取
  3 / 10 ターン目      攻:B  守:A
  A:16                B:10
─────────────────────────
   [4]  [6]  [8]  [10]  [12]
─────────────────────────
  Aさん、配置してください
  [ハート] [シールド]    [確定]
```

- 上段: 左に[履歴]ボタン、右に目標点(45点先取)
- 2段目: 現在のターン数と、その時点の攻守。攻守は1ターンの中で入れ替わる
- 3段目: 両者の得点
- 中央: 箱を一列に並べる
- 下段: フェーズごとに案内文と操作ボタンが切り替わる(配置は[ハート][シールド][確定]、攻撃は[攻撃]、判定後は[次へ]だけ)
- [履歴]は配置中と攻撃選択中も押せる。履歴は公開済みの情報だけなので、開いても配置は見えない

### 交代画面(ローカル対戦のみ、オーバーレイ)

1. 配置前: 「Aさんの配置です。Bさんは画面を見ないでください。」と「準備OK」ボタン(配置側が押す)
2. 配置後: 「配置が完了しました。Bさんに端末を渡してください。」と「Bさんです」ボタン(攻撃側が押す)。箱の中身は表示しない

### 判定・公開(REVEAL)

- 攻撃が確定すると、全部の箱を透過して、ハートとシールドの位置を両者に見せる
- 攻撃された箱を強調し、結果を1行で表示する(例: 「ハート命中 B +10」「シールド発動 A +6」「空箱 得点なし」)
- 壊れた箱は演出なしで灰色にして残す
- 自動では進まず、[次へ]で進める

### 履歴ポップアップ

上部に[← 試合に戻る]。攻撃処理1回につき1件を、縦に並べる。一番上が最新で、10ターンなら最大20件。

```
← 試合に戻る
────────────────
7ターン目       攻:B  守:A
 [4] [6❤] [10🛡] [12]
              ▲攻撃
 A:16(+6)  B:10
────────────────
```

- 箱は、その時点で生きていた箱だけを、左から小さい順に点数付きで表示する
- ❤がハート、🛡がシールドの位置、▲が攻撃された箱
- 得点は攻撃処理後の累計。得点した側の点数の横に(+N)を付け、+Nの文字は緑
- 得点が動かなかった時は、AとBの両方に(+0)を付け、+0の文字は黒
- 背景が暗い場合は、黒文字が読めるよう背景色か文字色を調整する

### 結果画面

```
        Aの勝利
   A:46      B:38
 決着: 45点先取

 [もう一度] [履歴を見る] [ホームへ]
```

- 勝者を表示する。引き分けは「引き分け」と表示する
- 決着の理由を表示する(45点先取、10ターン終了の得点比較、同点時は先に到達したターン)
- [もう一度]は、同じモードですぐ新しい試合を始める。最初の攻撃側は試合ごとに決め直す
- [履歴を見る]は、試合中と同じ履歴ポップアップを開く

## プレイヤーとCPU、コード構成

### プレイヤーの共通インターフェース

人間もCPUも、同じ2つのメソッドを実装する。どちらも Promise を返す(人間は画面の入力を待つため)。ルール層は、相手が人間かCPUかを知らない。

```js
// js/players/playerController.js(基底クラス)
export class PlayerController {
  /** @returns {Promise<{heart: number, shield: number}>} 箱の点数で指定 */
  async choosePlacement(view) { throw new Error('not implemented'); }

  /** @returns {Promise<number>} 攻撃する箱の点数 */
  async chooseAttack(view) { throw new Error('not implemented'); }
}
```

GameView には、プレイヤーが見てよい情報だけを入れる。

- 生きている箱の点数(昇順)
- 両者の得点、ターン数、何回目の攻撃処理か
- 自分が攻守どちらか
- 公開済みの履歴(履歴画面と同じデータ)

現在の配置は GameView に入れない。攻撃側に渡す時点でハートの位置が存在しないので、CPUが配置を見てしまうことが構造的に起きない。

### 実装するプレイヤー

| クラス | 挙動 |
| --- | --- |
| HumanController | 画面の入力を待つ(クリックやタップで Promise を解決する) |
| CpuRandomController | 配置は、重複しない2つの箱を無作為に選ぶ。攻撃は、生きている箱から無作為に選ぶ |

将来、履歴を読む賢いCPUを足す時も、同じ GameView の履歴を読む形で差し替えられる。

### 進行(gameFlow.js)

防御側に配置を聞く、攻撃側に攻撃を聞く、判定する、履歴に追加する、終了判定をする、を繰り返す。ローカル対戦では、PLACE_READY と HANDOFF の交代画面を挟む。

### ファイル構成

```
index.html            # 1ページ。ホーム・ゲーム・結果の表示をここで切り替える
package.json          # {"type": "module"} だけを書く(node でES Modulesを読むため)
css/
  style.css
js/
  main.js             # 起動、画面の切り替え、モード選択
  core/               # ルール層(DOMに触れない。node でテストできる)
    constants.js, gameState.js, rules.js, placement.js, gameView.js
  players/
    playerController.js, humanController.js, cpuRandomController.js
  flow/
    gameFlow.js       # 配置→攻撃→判定→履歴→終了判定の進行
  ui/
    home.js, game.js, result.js, history.js, handoff.js
tests/
  rules.test.js       # node --test で実行
docs/
  spec.md             # この仕様書
```

### 実装の順序と検証

1. ルール層を先に作り、`node --test` で10ターン回すテストを書く。ランダム同士で何千試合か回して、45点先取と10ターン終了の両方で決着し、エラーが出ないことを確認する
2. ランダムCPU対戦をゲーム画面につなぐ
3. ローカル対戦と交代画面を足す
4. 履歴ポップアップと結果画面を足す
5. GitHub Pagesに公開して、PCとスマホのブラウザで動作を確認する

仕様にない挙動は実装せず、質問として報告する。ローカルで確認する時は、簡易サーバー(例: `python -m http.server`)を使う。`file://` で開くと、ES Modules が読み込めない。

## 対象外と未決定事項

### プロトタイプでは実装しない(後で足す)

| 要素 | 内容 |
| --- | --- |
| アイテム | 4種。マッチング時に1つ選び、攻撃用は攻撃の前、防御用は配置の前に使用を宣言する。宣言は相手に見え、実際に使わなければ消費されない |
| 点数配分の切り替え | マッチング時に3パターンから選ぶ。4/6/8/10/12、1/5/7/9/15、2/3/4/10/11(各約33%)。並べ方のルールは全パターンで共通 |
| 通信対戦 | 方式は未定 |
| 制限時間、ポーズ画面、演出、ルール説明画面 | ホームと対戦の流れが固まってから検討する |

### アイテム4種(参考)

| 区分 | 名称 | 効果 |
| --- | --- | --- |
| 攻撃用 | レントゲンレンズ | 指定した1箱に、何か(ハートかシールド)が置かれているかだけが分かる |
| 攻撃用 | ゴールデンハンマー | そのサイクルの最高得点の箱を除き、ハート的中時の得点を1.5倍にする(端数は切り捨て) |
| 防御用 | レプリカシールド | 箱の破壊を防ぐが、得点は入らない。3つ目の仕込みとして追加で置く |
| 防御用 | ボックスリスポーン | 破壊済みの箱を1つ復活させ、仕込みを決め直す。復活直後に必ず相手の攻撃を挟むため、防御用にしている |
